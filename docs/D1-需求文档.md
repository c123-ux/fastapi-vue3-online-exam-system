## 1. 项目背景与目标

### 1.1 背景
本项目是全栈学习路线的第三个实战项目（① FastTask → ② 短链服务 → **③ 在线考试系统** → ④ 主项目 AI 任务协作平台）。前两个项目分别覆盖「测试驱动 + 任务调度」与「读多写少 + 高并发 ID 映射」，本项目补齐**教育场景的业务深度**：多角色权限、判分引擎、限时一致性、幂等控制。

### 1.2 目标
1. **真正从零动手实现**一个可给本校师生试用的在线考试系统，积累「真实用户」简历素材；
2. 练透四个技术点：**RBAC 角色权限**、**判分逻辑**、**Redis TTL 驱动的限时控制**、**防重复提交（幂等）**；
3. 与后续主项目（任务协作平台）形成业务广度互补。

### 1.3 范围
- **做**：F1~F11 后端全部功能 + 完整测试（P0/P1）；F11 仅计数（DB 字段，接口并入 S6）；F12 前端本期不做（P2）。
- **不做**：Vue3 前端、Excel 题库导入导出、切屏强制交卷、题目乱序、refresh token、fakeredis 等库外测试组件（列入 D4 后续优化）。

## 2. 角色与权限（RBAC）

### 2.1 角色定义
| 角色 | 标识 | 职责 |
|---|---|---|
| 老师 | `teacher` | 题库 CRUD、分类管理、手动组卷、发布/关闭考试、**读学生作答并批改简答题**、查看全班成绩与统计 |
| 学生 | `student` | 查看已发布考试、开始考试（限时）、逐题作答（支持续考）、提交、查自己的成绩与记录列表 |
| 未认证 | — | 仅注册、登录、健康检查 |

### 2.2 访问控制总规则（v1.1 统一口径，v1.2 定死判定顺序）
- **判定顺序固定为：401（未认证）→ 403（角色不符）→ 404（资源不可见/不归属）→ 400/409（业务规则）**。顺序不同结果不同，实现与用例都以此为准。
- **角色不符 → 403**（学生访问老师接口，或反向）；
- **角色相符但资源不归属你 → 404**（跨用户访问他人考试记录/成绩/作答；非创建者老师访问他人试卷的管理/统计/批改；学生访问未发布试卷）——统一隐藏资源存在性，防自增 ID 顺序探测；
- **同一条 404 对「资源不存在」与「存在但不属于你」必须返回完全相同的 `code` 与 `message`**（否则 404 本身就成了一台探测机）；
- 路径参数类型不合（如 `/api/exams/abc`）→ **422**（实测 FastAPI 行为，不当作 404 处理，见 D2 §5.1）；
- 老师注册需持有注册码（`TEACHER_REGISTER_CODE` 环境变量），否则 403（补防线，见 FR-01）。

## 3. 功能需求（FR）

编号规则：`FR-XX` 对应需求文档 `F` 序号。D3 测试用例**不硬凑同号**，以 M2 产出的「FR ↔ TC 对照表」为准（需求文档自身 FR-05↔TC-I-05 的同号约定实际不成立，已留痕）。

### FR-01 用户注册/登录与角色（P0，对应 F1）
- **描述**：注册（用户名唯一、bcrypt 存密码、角色 teacher|student）；登录签发 JWT（含 `role` claim）。**教师注册必须携带注册码**（env `TEACHER_REGISTER_CODE`），错误/缺失 → 403。**用户名统一小写归一**（注册与登录均 `strip().lower()` 后存储/比对），`utf8mb4_unicode_ci` 下大小写不敏感是明确行为契约。
- **输入**：`POST /api/auth/register {username, password, role, full_name?, teacher_code?}`；`POST /api/auth/token {username, password}`（JSON，非表单）。
- **输出**：注册返回用户信息（不含密码哈希）；登录返回 `{access_token, token_type, role}`。
- **验收口径**：角色正确写入；先注册 `ABC` 再注册 `abc` → 409；无注册码/错码注册 teacher → 403；密码 bcrypt 可验不可逆；无 token 访问受保护接口 401。

### FR-02 题库管理（P0，对应 F2）
- **描述**：老师维护题目：四种题型 `single`/`multiple`/`judge`/`short`；含分类、难度（easy|medium|hard）、选项 JSON、正确答案。**被 published/closed 试卷引用后，题目内容锁定**（content/options_json/correct_answer/type 修改 → 409 `QUESTION_LOCKED`；分类/难度不参与判分，允许改）；删除被引用题目 → 409 `QUESTION_IN_USE`。
- **题型校验矩阵**（结构/长度违规 → 422；跨字段业务规则违规 → 400）：
| 题型 | options 要求 | correct_answer 要求 | 400 情形示例 |
|---|---|---|---|
| single | 2~6 个，每个 ≤500 字符 | 单个大写字母，且必须是 options 中的选项 | 答案字母越界（如存 "E"） |
| multiple | 2~6 个 | ≥2 个大写字母，排序逗号分隔（如 `A,C`），均在 options 内 | 正确项 <2；字母越界 |
| judge | 禁止传 options | `T` / `F` | 传了 options |
| short | 禁止传 options | **允许空串**（可存参考答案/关键词，仅批改参考用，不参与自动判分） | 传了 options |
- **长度上限**（超限 422）：content ≤ 5000；学生作答 ≤ 1000；批语 ≤ 255；username ≤ 50。
- **验收口径**：学生调用 403；矩阵中每格失败路径可测；锁定规则可测。

### FR-03 手动组卷（P0，对应 F3）
- **描述**：老师从题库勾选题目并**逐题设置分值**组卷；`total_score`（DB 字段）由系统求和，响应中一律叫 `full_score`。支持 `GET /api/papers/{id}` 卷面详情（创建者，含题目与答案）。
- **输入**：`POST /api/papers {title, duration_minutes, start_at, end_at, questions: [{question_id, score}]}`。
- **输出**：试卷对象（初始 `draft`）；详情含 items 列表。
- **验收口径**：题目不存在 404；分值 ≤ 0 400；重复加题 409；`end_at <= start_at` 或时长 ≤ 0 400。随机抽题组卷列 P1 预留（见 D2 §6.7）。

### FR-04 试卷管理与发布（P0，对应 F4）
- **描述**：状态机 `draft → published → closed`（单向）；发布校验：≥1 题、full_score > 0、时间窗合法；**`deadline_at = min(开考时刻 + duration_minutes, end_at)`**（时间窗截断口径，写死）；**close 只拦新开考**，进行中记录按原 deadline 自然清算。
- **验收口径**：空卷/零分卷发布 400 `EMPTY_PAPER`；学生列表只见 published（未发布试卷对学生 404 隐藏）；非创建者老师管理他人试卷 404。

### FR-05 学生参加考试（P0，对应 F5）
- **描述**：start 有且仅有两个分支——**① 新建**：校验 published + 时间窗 + 无历史记录 → 建 exam_records（`deadline_at` 只在此刻写入）+ 判分基线快照 + Redis 会话；**② 幂等续考**：已有记录且未交 → **禁止修改 deadline_at**，会话缺失才按剩余时间重建（TTL 只减不增）。已交卷记录再 start → 409。逐题作答实时落库（upsert），**answer 必须校验记录状态与剩余时间**。`GET /api/exams`（我的考试记录，分页）供学生换设备找回 record_id。
- **输入**：`POST /api/exams/{paper_id}/start`；`POST /api/exams/{record_id}/answer {question_id, answer}`；`GET /api/exams/{record_id}`（续考响应）。
- **输出**：start 返回 `{record_id, paper_title, questions[], remaining_seconds, deadline_at}`；answer 返回保存确认。
- **验收口径**：连续 start 三次 `deadline_at` 不变、`remaining_seconds` 单调不增；已交卷 start 409；超期 answer 409 `EXAM_TIME_UP` 并触发清算；对非 in_progress 记录 answer 409；题目不属于本卷判分基线 400；**续考响应与 start 响应任何字段都不出现 correct_answer/reference_answer**（用白名单响应模型，见 D2 §5.4）。

### FR-06 限时控制（P0，对应 F6）
- **描述**：以**服务端**为唯一时间基准，应用层单点时钟（`time_utils.now()`，测试可注入）。开考建 Redis 会话，**字符串 SET + EX 原子带 TTL**（禁用 Hash 存会话——Hash 不自带 TTL，实测 TTL=-1 即永不过期）；TTL = 截止 + 30 秒宽限（可配）− 当前；`TTL` 返回 **-1（存在但无过期）视为异常态，立即按 DB deadline 重设**；**剩余时间由 DB 计算**：`remaining_seconds = max(0, deadline_at − now)`（v1.2：不再依赖 Redis，保证 NFR-08「读路径不依赖 Redis」成立；Redis TTL 只用于判活自检与发现 TTL=-1）。到点未交：宽限内正常提交；超过宽限按已存答案判为超时交卷，**照常进入统计**。
- **验收口径**：开考后 `TTL exam:session:{rid} > 0`（防漏 EXPIRE，有专测）；截止计算正确；超时交卷 `submit_kind=timeout` 且分数计入统计；**Redis 未运行时续考响应仍能给出 remaining_seconds**（NFR-08 联动用例）；改本地时间无效。

### FR-07 判分与批改（P0，对应 F7）
- **描述**：提交时自动判客观题：单选/判断严格匹配；多选**集合全等、全对才给分**；**未作答客观题按 0 分补齐**（is_correct=false）；**未作答简答题直接 0 分定稿**（题级 `review_status=skipped`，不进待批）；**已作答简答题进待批**（题级 `review_status=needs_review`），由老师批改后置 `reviewed`；无待批则记录级 `review_state=final`（成绩定稿）。**题级与记录级字段刻意不同名不同值域**（v1.2，防混淆）：`answers.review_status ∈ needs_review|reviewed|skipped`，`exam_records.review_state ∈ pending|final`。批改仅限 `type=short`（其他题型 → 400）；批改分值 0 ≤ x ≤ 该题卷面分值；批改事务对记录行 `FOR UPDATE`，防并发丢更新。
- **输入**：提交自动触发；`POST /api/exams/{record_id}/review {question_id, score, comment?}`。
- **输出**：提交返回 `{earned_score, pending_review_count, submit_kind, ...}`；批改返回最新总分与剩余待批数。
- **验收口径**：对/错/少选/错选/未答/未答简答各有断言；非 short 批改 400；越界批改 400。

### FR-08 成绩查询与作答读取（P0，对应 F8）
- **描述**：学生查自己成绩（auto_score/manual_score/earned_score/full_score/pending_review_count/submit_kind）；老师读学生作答：**`GET /api/exams/{record_id}/answers`（仅该卷创建者）返回逐题 `student_answer` 与 `reference_answer`**——这是批改的唯一数据来源（v1.0 缺口 A6；v1.2 与 D2 口径统一）。老师查全班成绩 `GET /api/papers/{id}/results`。
- **泄露口径（v1.2 写死，消除 v1.1 的 D1/D2 互斥）**：**学生侧任何响应**（start / 续考响应 / submit / score / exams 列表）都不含 `correct_answer`、`reference_answer`、`student_answer` 之外的判分依据；**老师侧 `/answers` 含 `reference_answer`**（批改必须看参考答案才公平），其取值来自记录自己的判分基线快照。成绩响应对任何角色都不含正确答案。
- **实现约束**：禁止把 ORM 记录对象直接输出为响应（`snapshot_json` 内含答案）；一律经 schemas 白名单模型（见 D2 §5.4）。
- **验收口径**：跨用户访问他人记录/成绩/作答 → **404**（统一存在性隐藏）；学生访问 results/stats/answers/review → 403；字段命名全局统一 `earned_score`（已得）/`full_score`（满分），无 `total`/`total_score` 混用；**自动化断言：学生身份调用每个已实现接口，响应正文不含字符串 `correct_answer` 与 `reference_answer`**（TC-I 公共用例，见 D3）。

### FR-09 成绩统计（P1，对应 F9）
- **描述**：老师查看某试卷统计。**分母口径（写死）**：已交卷记录数 = `status=final`（**含超时**，v1.0 缺口 B1 已修）；**平均分/最高/最低仅统计 `review_state=final` 的记录，且每个均值各自回报样本数**（v1.2：`avg_score` + `avg_scored_count`、`avg_auto_score` + `finished_count`，避免"35 人均分"与"40 人客观分均值"并排却看不出样本不同）；另返回 `timeout_count`、`pending_review_count`。每题正确率仅统计客观题：正确人数 ÷ **已交卷记录数**（未答即算答错，分母恒定）；简答题展示平均得分。
- **数据来源口径（v1.2 写死，N6）**：**判分读记录的判分基线快照**（`snapshot_json`）；**统计与卷面展示读 `paper_questions` + `questions`**（因 published 锁定规则二者恒等，而快照是每人一份 JSON、无法跨记录聚合）。本期**不提供 `PUT /api/papers`**——published 后题集与每题分值不可变（无接口即无路径，防从后门破坏判分基准）。
- **验收口径**：构造已知数据集（含超时者、未批改者）各项数字正确；分母为 0 时返回 0 而非报错；GROUP BY 合规（ONLY_FULL_GROUP_BY 真库可跑）；每个均值与其样本数在同一条断言里核对。

### FR-10 防重复提交（P1，对应 F10）
- **描述**：**权威闸门是数据库条件更新**：`UPDATE exam_records SET ... WHERE id=:rid AND status='in_progress'`，`rowcount==1` 的请求才拥有交卷权（InnoDB 行锁天然串行化并发）。Redis `SETNX` 降级为**快速失败的前置优化**，且**在 commit 成功之后才置标记**——判分失败回滚不会把学生锁死（v1.0 缺口 B3）。数据库 `(paper_id, student_id)` 复合唯一兜底防重复开考。
- **验收口径**：service 层并发调两次 submit（TestClient 单线程，不适用）仅一次成功、一次 409；模拟判分抛异常后重试提交可成功；重复提交 409 携带首次信息。

### FR-11 防切屏记录（P2，对应 F11）
- **描述**：前端 `visibilitychange` 上报（本期无前端），后端**只写 DB**：`UPDATE exam_records SET cheat_count = cheat_count + 1 WHERE id=:rid AND student_id=:me AND status='in_progress'`；**不建 Redis 计数键**（v1.0 的 `cheat:{rid}` 键删除——无读者、Redis 重启即漂移，属自造不一致）；只记录次数，不强制交卷。实现并入 S6。
- **验收口径**：上报 N 次 cheat_count=N；对他人记录/已交卷记录上报 → 404/409。

### FR-12 前端页面（P2，对应 F12）
- **描述**：Vue3 前端。**本期不做**，后端 + pytest 全绿后另起一轮评估。

## 4. 非功能需求（NFR）

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-01 | 性能 | **观察项**（不做验收数字）：试卷加载 < 500ms、提交 < 1s，用 `curl.exe -s -o NUL -w "%{time_total}\n" ...` 抽测记录进 D4；不引入压测工具（D4 不得编造数字） |
| NFR-02 | 一致性 | 时间以**服务端**为准且**单点生成**（`time_utils.now()`，判分/限时/清算全部经它取时间，测试 monkeypatch 此一处即可时间快进）；`deadline_at`/`started_at`/`submitted_at` 用 `DATETIME(3)` 消除秒级截断抖动；DB 是时间事实源，Redis 只判活；提交幂等 |
| NFR-03 | 安全 | 密码 bcrypt；JWT HS256 + 角色 claim，**有效期 240 分钟，且约束 `ACCESS_TOKEN_EXPIRE_MINUTES ≥ 最大考试时长 + 宽限 + 余量`**（v1.0 的 60 分钟会让学生第 60 分钟交不了卷）；教师注册码；学生侧任何响应不泄露 correct_answer/student_answer（后者仅 /answers 对创建者暴露）；跨用户资源 404 隐藏存在性 |
| NFR-04 | 幂等/防重 | 见 FR-10；重复 start 幂等且不续时；answer 为 upsert 且带状态/时间守卫 |
| NFR-05 | 可观测 | logging：INFO（开考/提交/判分完成）、WARNING（超时清算/重复提交拦截/越权）、ERROR（DB/Redis 异常）；格式 `时间 \| 级别 \| 模块 \| 消息`；禁止 print |
| NFR-06 | 可测试 | pytest 全绿、无逻辑性 skip（环境缺失=失败并打印启动命令，不算 skip）；覆盖率双口径：`--cov=app.services --cov-fail-under=80` 卡关 + `--cov=app` 仅报告；String 字段必须显式长度 |
| NFR-07 | 兼容 | Python **3.12.13**；MySQL 8.0.46 @3307 + utf8mb4；Redis **5.0.14.1 原生**（`D:\Redis`）；依赖锁精确版本（沿用项目一实测组合） |
| NFR-08 | 依赖韧性 | Redis 客户端带 `socket_connect_timeout=1, socket_timeout=1, health_check_interval=30`，统一捕获 `redis.exceptions.RedisError`；**启动期依赖不可用不阻塞启动**（ERROR + degraded）；**Redis 未起时写路径 fail-fast 500 + 清晰日志，读路径不依赖 Redis**；`/health` 恒 200 报 `{status, deps:{mysql, redis}}`（liveness 语义） |

## 6. 边界条件（EC）

> v1.1 重编号；引用处一律以本表编号为准（v1.0 的 EC-04~07 引用偏差已修正）。

| 编号 | 场景 | 系统行为 |
|---|---|---|
| EC-01 | 考试未开始（now < start_at）开考 | 400 `EXAM_NOT_STARTED` |
| EC-02 | 考试窗口已过（now > end_at）开考 | 400 `EXAM_ENDED` |
| EC-03 | 试卷已关闭（closed） | 400 `EXAM_CLOSED` |
| EC-04 | 学生访问未发布试卷（start/详情） | 404 `PAPER_NOT_VISIBLE`（存在性隐藏） |
| EC-05 | 宽限期内提交（deadline < now ≤ deadline+30s） | 正常判分，`submit_kind=normal` |
| EC-06 | 超过宽限期后提交（主动或清算触发） | 按已存答案判分，`submit_kind=timeout`，**照常进统计** |
| EC-07 | 超时且学生再未访问 | 惰性清算：学生查成绩/老师查 results/stats/同卷 start 触发；**DB 条件更新为闸门**，并发清算仅一方成功 |
| EC-08 | 重复提交同一记录 | 409 `ALREADY_SUBMITTED`，携带首次提交时间与当前得分 |
| EC-09 | 进行中重复 start | 幂等返回原记录：`deadline_at` 不变、remaining 单调不增；session 缺失按剩余重建；剩余 ≤ 0 → 转入清算 |
| EC-10 | 已交卷记录再 start | 409 `ALREADY_SUBMITTED` |
| EC-11 | 超期后仍调 answer | 409 `EXAM_TIME_UP`，并触发清算（先清算后拒绝） |
| EC-12 | 对非 in_progress 记录 answer | 409 |
| EC-13 | 多选题少选/错选/多选 | 均判 0 分（全对才给分） |
| EC-14 | 简答题未作答 | 直接 0 分定稿（题级 `review_status=skipped`），不进待批 |
| EC-15 | 简答题已作答未批改 | 该题 `score=NULL`、题级 `review_status=needs_review`；成绩接口返回 pending_review_count，earned_score 为当前累计 |
| EC-16 | 客观题未作答 | 按 0 分补齐（is_correct=false, score=0） |
| EC-17 | 空卷 / full_score=0 发布 | 400 `EMPTY_PAPER` |
| EC-18 | 题目分值 ≤ 0 / 缺失 | 400，拒绝加入试卷 |
| EC-19 | 跨用户访问他人考试记录/成绩/作答 | 404 `RECORD_NOT_VISIBLE`（隐藏存在性） |
| EC-20 | 角色不符（学生访问题库/统计/批改等） | 403 `ROLE_FORBIDDEN` |
| EC-21 | 删除被引用题目 | 409 `QUESTION_IN_USE` |
| EC-22 | 修改被 published/closed 试卷引用题目的内容/选项/答案/题型 | 409 `QUESTION_LOCKED`（判分基准保护） |
| EC-23 | 用户名重复（含仅大小写不同） | 409 `USERNAME_EXISTS` |
| EC-24 | answer 的题目不属于本卷快照 | 400 `QUESTION_NOT_IN_PAPER` |
| EC-25 | JWT 缺失/过期/伪造 | 401（考试期间过期：重登即可，答案已逐题落库不丢失） |
| EC-26 | 教师注册码缺失/错误 | 403 `INVALID_TEACHER_CODE` |
| EC-27 | 批改非 short 题 / 批改分值越界 / 批改他人记录 | 400 / 400 / 404 |
| EC-28 | 提交与清算并发、双击提交、批改与清算并发 | DB 条件更新/行锁保证仅一方生效，另一方读到 final 后正常 409，**不出现 500 与脏写** |
| EC-29 | Redis 未运行（原生实例默认不运行） | 开考/作答/交卷 fail-fast 500（ERROR 日志提示启动命令）；score/results/stats 不依赖 Redis 正常返回；/health 报 degraded 恒 200 |
| EC-30 | 会话键 TTL=-1（漏 EXPIRE 异常态） | 判定为异常：立即按 DB deadline 重设过期，不视为「会话存在」 |
| EC-31 | 开考时窗口剩余时长过短（`end_at − now < 下限`） | 400 `EXAM_WINDOW_TOO_SHORT`；下限 = `min(60 秒, duration_minutes×60×10%)`（v1.2 新增，否则学生点开即超时、白生一条 0 分 timeout 记录） |
